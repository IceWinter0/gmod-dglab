# gmod-dglab

Garry’s Mod 与郊狼 DG-Lab 3.0 联动项目。通过注入式 Rust DLL 采集本机游戏状态，由独立桌面控制面板配置联动规则、强度和波形。

> 首版 v0.1.0 面向 Windows x64 与郊狼 3.0。APP 3.x 已通过用户实机测试；APP 4.x 为实验性适配，尚未完成实机验证。

## 功能与支持范围

- 仅支持 Windows 64 位与 GMod x86-64 / Chromium 分支。
- 仅支持郊狼 3.0 硬件，支持 DG-Lab APP 3.x；APP 4.x 提供实验性适配。
- 在本机注入 Rust DLL，无需安装服务器插件或修改服务器。
- 根据本地玩家血量与生命状态变化，触发受伤、死亡和重生联动。
- 提供双通道强度、波形预设、规则配置、事件日志和停止操作。

## 架构

```text
GMod 中的 Rust DLL
    │ 本机事件与心跳
    ▼
独立桌面控制器
    ├─ Rust 控制核心：规则、限幅、调度与设备连接
    └─ 桌面面板：配置、状态与日志
    │
    ▼
DG-Lab APP → 郊狼 3.0
```

客户端只能使用实际收到的信息。血量下降属于近似受伤信号，无法保证还原服务器上的每次伤害、攻击者或伤害类型。

## 发布与验证

APP 3.x 与郊狼 3.0 已通过用户实机测试；APP 4.x 当前仅完成协议和本机 WebSocket 验证。换图、不同服务器环境和其他 APP 小版本的行为仍需持续验证。

## 已实现功能

已提供 Windows x64 玩家采样 DLL、本机诊断接收器，以及共享事件协议与玩家状态机。接口、通信与掉血、死亡、重生事件已通过本次实机测试；换图和断线重连仍待验证。未解析到的护甲字段明确标记为不可用。

发布的 Windows 便携包包含面板应用程序与 bin 目录中的采样 DLL。

中文桌面控制面板已实现游戏状态、A/B 规则配置、波形参数预览、事件日志与停止操作。配色参考官方 APP 3.x，内置 24 种官方郊狼波形，同时支持用户导入 JSON 波形。规则由 Rust 核心计算，支持基础强度、按掉血点数累加、强度限幅、独立死亡增量与冷却、重生清空增量和失联停用。已加入 APP 3.x/V3 与 APP 4.x/V4 的扫码配对、强度回传、限幅、波形发送和重置；协议已通过本机 WebSocket 测试，APP 3.x 与郊狼 3.0 已通过用户实测，APP 4.x 实机输出仍待验证。原创参数预览波形已移除，旧配置中的平稳、渐入渐出、双峰会迁移为官方“呼吸”，其他参数保留。

## 面板使用

面板分为“联动控制”“波形管理”“设置”。顶部状态与“重置强度”按钮始终显示，规则保存和联动启停集中在底部；跨页操作保留未保存的规则草稿。在“设置”中连续点击版本号七次可解锁“开发者工具”，查看心跳与完整事件日志。点击间隔超过三秒会重新计数，开发者模式仅当前会话有效，可主动退出。

1. 关闭旧诊断接收器，打开桌面面板；默认监听 `127.0.0.1:47831`。端口占用会提示错误，可以修改为其他回环端口。
2. 点击顶部游戏状态旁的“连接游戏”，自动寻找 GMod x64 并加载随包的采样 DLL。失败后可点“重试连接”；多个游戏客户端时选择 PID，Chromium 网页渲染与网络子进程会被排除。游戏刚启动时请等待加载完成。已经加载采样 DLL 时会跳过注入并等待重连，不支持热替换旧 DLL。
3. 在 A/B 通道勾选“开启输出”，设置基础强度、上限、映射率和受伤持续时间，点击“保存规则”。首次启动上限为零、联动停用。
4. 游戏与设备连接且存在存活玩家后，点击“启用输出”；启用后保持基础强度；受伤时查看强度和事件日志，增量到期恢复基础强度。死亡规则默认关闭。
5. “重置强度”立即归零并停用联动、清空临时增量；游戏失联后需重新启用。重启面板保留规则配置，但不保留启用状态。

面板联动的换图、断线和重连行为仍需游戏实测。护甲尚不可用，不参与规则。波形图显示相对幅度曲线（实线）和频率编码（虚线），并非设备真实电流测量。

## 强度与冷却规则

每个已开启通道的强度为 `min(强度上限, 基础强度 + 受伤增量 + 死亡增量)`。映射率分别设置 A/B 通道，单位为每掉血 1 点增加的强度；小数增量先累加，再对最终强度取整。受伤增量累加至通道可用范围，每次受伤刷新受伤持续时间。死亡保留已有受伤增量，另加死亡强度；致命掉血不会重复计入受伤增量。

受伤增量来源可选“连续受伤累加”或“按缺失生命值计算”。后者只对存活玩家生效，按 `max(0, 最大生命值 - 当前生命值)` 持续计算，回血时降低，不使用受伤持续时间和冷却；死亡后由独立死亡规则处理。映射单位可为每 1 点血量或每 1% 最大生命值，A/B 分别设置；例如最大生命值 200、当前 150，缺失 25%，每 1% 增加 2 强度时增量为 50。需要最大生命值但该数据不可用时跳过对应计算。

受伤与死亡持续时间分别为 100～10000 ms，冷却分别为 0～60 秒（0 表示关闭）。各自增量到期后进入各自冷却，冷却期间该类事件仍记录，但不增加或刷新增量，另一类规则不受影响。已取消原连续 5 秒中断限制。死亡高级设置可选择所有已开启通道、仅 A 或仅 B。

重生清空临时增量并恢复基础强度，已有冷却继续；尚未到期的增量因重生提前结束时，从重生时开始该类冷却。停止或失联则归零并停用。旧配置的强度下限迁移为基础强度，新增映射率默认 1、点数单位、累加模式；启动时联动仍处于停用状态，请确认新参数后再启用。

## 自行导入波形

在“波形管理”页面选择“导入波形 JSON”。A/B 通道的下拉框用于选择当前波形，点击“保存规则”生效；通道内同步显示曲线预览。支持单个对象或对象数组，`raw` 可作为 `frames` 的别名：

```json
{"name":"我的波形","frames":["0A0A0A0A00643200"]}
```

每帧为 16 个十六进制字符：前四字节为频率编码，后四字节为相对幅度；一帧包含四个 25 ms 参数窗口。频率编码范围为 10..240、幅度为 0..100，允许全零补位。文件和保存后的导入库最多 1 MiB，最多 128 种波形，每种最多 4096 帧；图形预览最多抽样 1024 点，完整帧仍保留。非法批次不会部分导入，相同名称和数据自动去重。

导入数据保存在当前用户 `LOCALAPPDATA/gmod-dglab/waveforms.json`；导入不会自动启用输出或发送设备输出。当前仅支持上述 JSON 格式，不直接解析 APP 导出的 ZIP 或二维码。


## 设备连接

1. 在手机 APP 中连接郊狼 3.0；在面板“设备连接”中选择 APP 3.x 或 APP 4.x，点击“连接设备”。
2. 打开 APP 的 SOCKET 控制并扫描面板二维码。默认使用官方中继，也可在设置页的“设备连接高级设置”填写兼容的 ws/wss 地址。
3. 等待强度与上限回传。APP 4.x 支持设备选择，面板只列出郊狼 3.0；多个 APP 接入时只控制当前配对的一端。
4. 保存 A/B 规则，点击“启用输出”。配对本身不会启动输出；启用时先清理原有任务并归零，再按规则运行。实际发送的强度不会超过面板和 APP 上限。
5. “当前强度”为 APP 回传，“联动强度”为规则计算结果。无回传显示“—”；回传不是设备真实电流测量。
6. “重置强度”停用输出、清理波形并请求 A/B 归零。APP 3.x 无清理确认接口，零强度回传不能证明波形队列清理已完成；APP 4.x 另外跟踪任务回复。未收到确认会明确提示。
7. 游戏、APP 或设备断开后保持输出停用，重新连接后需手动启用。断网时不能保证归零指令送达，请在 APP 中确认实际状态。

设备连接设置保存在当前用户 `LOCALAPPDATA/gmod-dglab/device.json`，不保存配对标识或启用状态。APP 3.x 配对后如一直等待状态，请确认蓝牙连接，并在 APP 中调整一次强度上限以刷新回传。

## 便携包与内置连接

完整解压发布包后运行 `gmod-dglab.exe`，并保留同目录 `bin/gmod_dglab_collector.dll`。面板从自身目录找 DLL，不依赖启动时的工作目录。启动面板不会自动注入，点击“连接游戏”后才执行；加载完成仍需收到有效认证握手才显示已连接。

找不到游戏时先启动 Windows x64 GMod；权限不足时检查面板与游戏的运行权限。连接超时可查看 `%LOCALAPPDATA%/gmod-dglab/collector-diagnostic.log`。如果已有旧 DLL 无法连接或游戏版本未适配，需要退出游戏后再启动；面板不热卸载、不中断游戏、不自动提权。未确认完成的加载会保留进程标记，重新打开面板也不会重复注入；异常时请重启游戏。新 DLL 携带 PID，需与新面板配套使用；新面板兼容单个游戏进程的旧 DLL 握手。

游戏连接成功不会自动启用输出规则。升级后确认参数，再手动启用输出。

`./scripts/package-preview.ps1` 构建并生成 EXE＋bin DLL 的便携 ZIP、源码 ZIP 与 SHA256；`-SkipBuild` 仅打包已构建产物。源码包明确排除私有 docs 和构建缓存。加上 `-Release` 生成正式 v0.1.0 发布包；默认仍生成带时间戳的开发包。请完整解压并保留 bin 目录。

## 本地构建

需要 Windows x64 的 Rust MSVC 工具链、Visual Studio C++ 构建工具、Node.js 与 WebView2 Runtime。先构建前端，再构建桌面宿主：

```powershell
cd desktop
npm ci
npm test
npm run build
cd ..
cargo test --workspace
cargo build --release -p gmod-dglab-desktop
```

桌面程序生成于 `target/release/gmod-dglab-desktop.exe`。采集端可用 `cargo build --release -p gmod-dglab-collector` 构建；不要覆盖游戏中已经加载的 DLL 文件。
