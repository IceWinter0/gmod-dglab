# GMod × 郊狼

让 Garry’s Mod 中的受伤、死亡和血量变化与郊狼强度联动。通过桌面面板设置 A/B 通道的强度、波形和联动规则，无需安装服务器插件，也不依赖服务器开启客户端 Lua 权限。

## 下载与使用

### 使用前准备

- Windows 64 位系统。
- Garry’s Mod 的 **x86-64 / Chromium 分支**。
- 郊狼 **3.0** 硬件与 DG-Lab APP（推荐使用 APP 3.x；APP 4.x 目前为实验性支持）。

### 使用教程

1. 前往 [Releases](https://github.com/IceWinter0/gmod-dglab/releases/latest) 下载 `gmod-dglab-0.1.1-windows-x64.zip` 并完整解压（请保留 `bin` 目录），运行 `gmod-dglab.exe`。
2. 启动 GMod x64 并进入游戏地图，点击面板顶部的“连接游戏”；如果连接失败，可以点击“重新连接”重试。
3. 在手机上打开 DG-Lab APP 连接郊狼 3.0，开启 **SOCKET 控制**；在面板中选择对应的 APP 版本，点击“连接设备”并扫码配对。
4. 等待设备状态同步后，勾选需要启用的 A/B 通道，设置基础强度、强度上限、映射率和当前波形，点击“保存规则”。
5. 确保游戏和设备均已连接且角色处于存活状态，点击底部“启用输出”即可开始联动。
6. 需要停止时点击“停用输出”，或点击右上角“重置强度”立即清空临时增量并请求设备归零。

出于安全考虑，首次启动时默认强度上限为 0，输出处于关闭状态；每次断线重连或重启面板后，都需要手动点击“启用输出”（规则设置会自动保留）。

面板上的“当前强度”来自 APP 同步，“预期强度”为规则计算值，两者均为软件控制数值。如果遇到断网等异常情况，请直接在 APP 中确认或关闭输出。

## 联动规则

A/B 通道可以分别设置基础强度、强度上限、映射率和波形。最终输出强度按以下公式计算：

```text
基础强度 + 受伤增量 + 死亡增量
```

小数部分的增量会先保留并累加，求总和后再四舍五入；最终下发的强度不会超过面板和 APP 中设置的通道上限。

### 受伤联动

受伤增量支持两种计算模式：

| 模式 | 效果 |
| --- | --- |
| 连续受伤累加 | 每次掉血增加强度并刷新持续时间，到期后恢复至基础强度。 |
| 按缺失生命值计算 | 根据最大生命值与当前血量的差值持续增加强度，回血时随之降低（此模式不使用持续时间与冷却）。 |

映射单位可在 A/B 通道分别选择“每 1 点血量”或“每 1% 最大生命值”。例如最大生命值为 200、当前血量为 150（缺失 25%），若映射率为每 1% 增加 2 强度，则受伤增量为 50。

受伤持续时间可设为 **100～10000 ms**，冷却可设为 **0～60 秒**（设为 0 即关闭冷却）。增量到期后会进入冷却，冷却期间不会继续累加或刷新受伤强度。

### 死亡与重生

死亡联动可额外叠加一档强度，支持独立设置增量、持续时间、冷却以及生效通道（所有已开启通道 / 仅 A / 仅 B），并与受伤增量共享通道上限。触发死亡的当次掉血不会重复计入受伤增量。

角色重生时会立即清空当前的临时增量并恢复基础强度；若原有增量被重生提前打断，对应冷却会从重生时刻开始计算。

## 波形选择与导入

程序内置了 **24 种官方郊狼波形**，在 A/B 通道的“当前波形”下拉框中选择并保存即可生效，下方会显示波形轮廓预览。

如需使用自定义波形，可前往“波形管理”页面点击“导入波形 JSON”，支持单个对象或对象数组，格式如下：

```json
{"name":"我的波形","frames":["0A0A0A0A00643200"]}
```

其中 `raw` 可作为 `frames` 的别名。每帧由 16 个十六进制字符组成：前四字节为频率编码（10～240），后四字节为相对幅度（0～100，允许全零补位），包含四个 25 ms 参数窗口。

波形库上限为 1 MiB（最多 128 种波形，每种最多 4096 帧），导入时会自动按名称和数据去重；若文件格式有误，整批导入会失败并保留原有数据。目前支持上述 JSON 格式，暂不支持直接导入 APP 导出的 ZIP 或二维码。

## Q&A

### 找不到游戏或连接失败

请确认启动的是 GMod Windows x64 分支，并等待游戏加载完成。存在多个游戏客户端时，可以在面板中选择对应进程（Chromium 辅助进程已自动过滤）。

如果提示权限不足，请检查面板与游戏的运行权限，或尝试以相同权限运行。若游戏更新后仍无法接入，可附上 `%LOCALAPPDATA%\gmod-dglab\collector-diagnostic.log` 提交反馈。

### 升级后仍使用旧 DLL

游戏运行期间无法直接替换已加载的 DLL。更新版本前请先关闭游戏，再解压新版本覆盖全部文件后重新启动。

### 扫码后一直等待设备状态

请确认手机 APP 已通过蓝牙连接郊狼并开启了 SOCKET 控制。使用 APP 3.x 时，可以尝试在手机端微调一次强度上限来刷新状态回传；若在 APP 4.x 下连接了多台设备，请在面板中选择郊狼 3.0。

### 已连接但没有输出

请检查 A/B 通道是否勾选了“开启输出”、通道强度上限是否大于 0、规则是否已保存，以及游戏角色是否处于存活状态，确认无误后点击“启用输出”。

### 修改连接地址

在“设置”中可以修改本机监听地址（默认 `127.0.0.1:47831`，仅支持回环地址）。设备连接默认使用官方中继；如需切换兼容中继，可在“设备连接高级设置”中修改 `ws/wss` 地址。

### 查看日志与配置

在“设置”页面连续点击版本号 **7 次** 可开启开发者模式，用于查看游戏心跳与完整事件日志（重启程序后自动恢复隐藏）。

导入的波形保存在 `%LOCALAPPDATA%\gmod-dglab\waveforms.json`，设备连接设置保存在同目录的 `device.json`。

## 兼容性说明

- 仅适配 Windows x64、GMod x86-64 / Chromium 分支与郊狼 3.0 硬件；APP 4.x 目前为实验性支持，如遇兼容问题建议换回 APP 3.x。
- 受伤联动依据本地玩家血量变化计算，不涉及护甲，也无法区分服务器上的具体伤害来源或伤害类型。
- 若部分服务器或地图未能正确同步最大生命值，百分比映射与缺失生命值模式会暂时跳过计算。
- 使用 APP 3.x 点击重置后，如果在面板上看到未收到归零确认的提示，建议在手机端再检查一下设备状态与波形队列。

## 从源码构建

需要 Windows x64 Rust MSVC 工具链、Visual Studio C++ 构建工具、Node.js 与 WebView2 Runtime。在项目目录执行：

```powershell
cd desktop
npm ci
npm run tauri -- build --no-bundle
cd ..
cargo build --release -p gmod-dglab-collector --target-dir target/injector-collector
```

编译产物位于 `target/release/gmod-dglab-desktop.exe` 与 `target/injector-collector/release/gmod_dglab_collector.dll`，运行时将 DLL 放入主程序同级的 `bin` 目录即可。

如需一键打包发布压缩包与源码包，可执行 `./scripts/package-preview.ps1 -Release`。
