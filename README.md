# GMod × 郊狼

让 Garry’s Mod 中的受伤、死亡和血量变化与郊狼强度联动。通过桌面面板设置 A/B 通道的强度、波形和联动规则，无需安装服务器插件以及要求服务器允许客户端lua。

## 下载与使用

### 使用前准备

- Windows 64 位系统。
- Garry’s Mod 的 **x86-64 / Chromium 分支**。
- 郊狼 **3.0** 硬件与 DG-Lab APP。APP 3.x 已通过实机测试；APP 4.x 为实验性支持，尚未完成实机验证。

### 使用教程

1. 前往 [Releases](https://github.com/IceWinter0/gmod-dglab/releases/latest)，下载 `gmod-dglab-0.1.1-windows-x64.zip` 并完整解压。保留 `bin` 目录，运行 `gmod-dglab.exe`。
2. 启动 GMod x64，进入游戏地图。点击面板顶部的“连接游戏”，等待显示已连接；连接失败时可点击“重新连接”。
3. 在手机 APP 中连接郊狼 3.0。在面板中选择对应的 APP 版本，点击“连接设备”，然后打开 APP 的 **SOCKET 控制**并扫描面板二维码。
4. 等待设备强度与上限回传。在 A/B 通道勾选“开启输出”，设置基础强度、强度上限、映射率和当前波形，点击“保存规则”。
5. 游戏与设备均已连接、玩家处于存活状态时，点击“启用输出”。启用后保持基础强度，并按联动规则增加强度。
6. 需要停止时，点击“停用输出”或“重置强度”。“重置强度”还会清空临时增量，并请求设备归零。

首次启动时强度上限为零，输出处于关闭状态。连接成功不会自动开启输出；游戏或设备断开后，重新连接也需要手动启用。重启面板会保留规则设置，但不会保留输出开启状态。

“当前强度”是 APP 回传的数值，“预期强度”是联动规则计算的数值，两者均不代表真实电流测量。断网时归零指令可能无法送达，请在 APP 中确认设备状态。

## 联动规则

A/B 通道可以分别设置基础强度、强度上限、映射率和波形。最终强度为：

```text
基础强度 + 受伤增量 + 死亡增量
```

小数增量先保留并累加，计算总和后四舍五入。最终发送的强度不会超过面板与 APP 中的通道上限。

### 受伤联动

受伤增量来源有两种模式：

| 模式 | 效果 |
| --- | --- |
| 连续受伤累加 | 每次掉血增加强度，并重新计算持续时间；到期后恢复基础强度。 |
| 按缺失生命值计算 | 根据最大生命值与当前血量的差持续增加强度；回血时降低，不使用受伤持续时间和冷却。 |

映射单位可选“每 1 点血量”或“每 1% 最大生命值”，A/B 通道分别设置。例如最大生命值为 200、当前血量为 150，缺失 25%；映射率为每 1% 增加 2 强度时，受伤增量为 50。

受伤持续时间可设为 **100～10000 ms**，冷却可设为 **0～60 秒**，0 表示关闭冷却。增量到期后开始冷却；冷却期间不会增加或刷新受伤增量。

### 死亡与重生

死亡联动额外增加强度，可独立设置增量、持续时间和冷却，并选择作用于所有已开启通道、仅 A 或仅 B。死亡增量与受伤增量共享通道强度上限，但两者的持续时间和冷却互不影响。致命掉血不会重复计入受伤增量。

重生时清空临时增量并恢复基础强度。已有冷却继续；如果重生提前结束了尚未到期的增量，则从重生时开始该类冷却。

## 波形选择与导入

内置 **24 种官方郊狼波形**。在 A/B 通道的“当前波形”下拉框中选择波形，点击“保存规则”生效；下方可预览当前波形。

“波形管理”页面用于浏览和导入波形。点击“导入波形 JSON”，支持单个对象或对象数组，例如：

```json
{"name":"我的波形","frames":["0A0A0A0A00643200"]}
```

`raw` 可作为 `frames` 的别名。每帧由 16 个十六进制字符组成：前四字节为频率编码，后四字节为相对幅度，包含四个 25 ms 参数窗口。频率编码范围为 10～240，幅度范围为 0～100，允许全零补位。

导入文件与保存后的波形库最多 1 MiB，最多 128 种波形，每种最多 4096 帧。相同名称和数据自动去重；存在无效数据时整批导入失败。导入不会自动开启输出。目前只支持上述 JSON 格式，不支持直接导入 APP 导出的 ZIP 或二维码。

## Q&A

### 找不到游戏或连接失败

确认启动的是 Windows x64 分支，并等待游戏加载完成。存在多个游戏客户端时，可在面板中选择对应进程；Chromium 辅助进程不会作为游戏客户端列出。

权限不足时，请检查面板与游戏的运行权限。采样 DLL 不按游戏版本号或时间戳拒绝接入，而是检查接口注册、函数指令特征和玩家属性结构；必要特征不匹配时停止采样。连接日志位于 `%LOCALAPPDATA%\gmod-dglab\collector-diagnostic.log`。

### 升级后仍使用旧 DLL

游戏中已经加载的 DLL 不支持直接替换。关闭游戏后更新完整便携包，再启动游戏并连接。

### 扫码后一直等待设备状态

确认 APP 已通过蓝牙连接郊狼，并已打开 SOCKET 控制。APP 3.x 可尝试在 APP 中调整一次强度上限，刷新状态回传。APP 4.x 接入多个设备时，需要在面板中选择郊狼 3.0。

### 已连接但没有输出

确认 A/B 通道已勾选“开启输出”、强度上限大于零、规则已保存，并已点击“启用输出”。玩家需要处于存活状态才能开启输出。

### 修改连接地址

在“设置”中可以修改本机监听地址，默认是 `127.0.0.1:47831`，仅支持回环地址。设备连接默认使用官方中继；需要使用兼容中继时，可在“设备连接高级设置”中修改 ws/wss 地址。

### 查看日志与配置

在“设置”中连续点击版本号 **7 次**可打开开发者模式，查看游戏心跳与完整事件日志。点击间隔超过 3 秒会重新计数，重启后恢复隐藏。

导入波形保存在 `%LOCALAPPDATA%\gmod-dglab\waveforms.json`，设备连接设置保存在同目录的 `device.json`。设备连接设置不保存配对标识或输出开启状态。

## 兼容性说明

- 当前仅支持 Windows x64、GMod x86-64 / Chromium 分支和郊狼 3.0。
- APP 3.x 已通过实机测试；APP 4.x 尚未完成实机测试。
- 受伤联动依据本地玩家血量变化计算，无法还原服务器上的每次伤害、攻击者或伤害类型；护甲不参与计算。
- 百分比映射与缺失生命值模式需要最大生命值；无法获取时跳过对应计算。
- 不同地图、服务器、换图和断线重连场景的兼容性仍需进一步验证。
- APP 3.x 不提供波形清理确认接口，零强度回传不能证明波形队列已清空。面板未收到归零确认时会显示提示。

## 从源码构建

需要 Windows x64 Rust MSVC 工具链、Visual Studio C++ 构建工具、Node.js 与 WebView2 Runtime。在项目目录执行：

```powershell
cd desktop
npm ci
npm run tauri -- build --no-bundle
cd ..
cargo build --release -p gmod-dglab-collector --target-dir target/injector-collector
```

面板生成于 `target/release/gmod-dglab-desktop.exe`，DLL 生成于 `target/injector-collector/release/gmod_dglab_collector.dll`。运行时将 DLL 放在面板程序旁的 `bin` 目录。

运行 `./scripts/package-preview.ps1` 可以构建并打包便携应用、源码和 SHA-256 校验文件。`-SkipBuild` 使用已有构建产物，`-Release` 生成正式版本文件名；默认使用带时间戳的开发包文件名。
